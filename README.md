# Yushiko — сайт сообщества

Полный стартовый проект: монохромный дизайн, адаптивная мобильная версия, Discord OAuth2, ограниченная по Discord ID админ-панель, новости, события, заявки, журнал действий и SQLite-резервные копии.

## Что внутри

- **Дизайн:** чёрный и белый — основные цвета; красный используется только как небольшой акцент. Анимация частиц/лепестков, мобильное меню, эффекты карточек и reduced-motion support.
- **Discord OAuth2:** серверный обмен кода, случайный `state`, профиль через Discord API. Секрет клиента не отправляется в браузер.
- **Админ-доступ:** только Discord ID из `DISCORD_ADMIN_IDS`.
- **Управление:** публикация/удаление новостей, создание/отмена событий, просмотр заявок и смена их статуса.
- **Аудит:** журнал административных действий.
- **Хранение:** SQLite для сайта и отдельное SQLite-хранилище сессий.
- **Защита:** Helmet, rate limits, CSRF-проверка административных изменений, лимиты тела запроса, параметризованные SQL-запросы.
- **Дополнительно:** публичная статистика online через Discord Widget API (если виджет включён), SEO/meta preview, 404, резервное копирование.

> Это готовый стартовый проект, который требует настройки Discord OAuth2 и тестирования в твоём окружении перед публичным запуском. Число участников сервера не выводится из Discord Widget API как достоверное общее число: публичный виджет показывает присутствующих онлайн. Если виджет отключён, число останется «—».

## 1. Что установить

1. Установи **Node.js 20 или новее**: https://nodejs.org/
2. Распакуй архив в отдельную папку.
3. Открой терминал/PowerShell в папке проекта и выполни:

```bash
npm install
```

## 2. Настрой Discord OAuth2

1. Открой Discord Developer Portal: https://discord.com/developers/applications
2. Создай приложение или выбери существующее.
3. В разделе **OAuth2** скопируй `Client ID` и создай/скопируй `Client Secret`.
4. В Redirects добавь точно такой адрес для локальной разработки:

```text
http://localhost:3000/auth/discord/callback
```

5. Скопируй `.env.example` в новый файл `.env`.
6. Заполни `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `SESSION_SECRET` и `DISCORD_ADMIN_IDS`.

### Как узнать свой Discord User ID

В Discord включи **Настройки → Расширенные → Режим разработчика**, затем нажми правой кнопкой по своему профилю/имени и выбери **Копировать ID пользователя**. В `DISCORD_ADMIN_IDS` впиши именно ID, не имя и не `@username`. Можно указать несколько ID через запятую.

Для `SESSION_SECRET` используй случайную длинную строку минимум 32 символа. Не используй пароль от Discord.

## 3. Запуск на компьютере

```bash
npm run dev
```

Открой http://localhost:3000. Для обычного запуска:

```bash
npm start
```

Админ-панель: http://localhost:3000/admin.html

## 4. Статистика Discord

В Discord открой **Настройки сервера → Виджет** и включи серверный виджет. Проверь `DISCORD_WIDGET_ENABLED=true` и верный `DISCORD_GUILD_ID` в `.env`. Публичный Discord Widget API может не показывать данные, если виджет отключён или Discord временно недоступен. Сайт останется рабочим, даже если статистика недоступна.

## 5. Резервные копии

- В панели администратора нажми **«Скачать резервную копию»**.
- Или останови/оставь сервер работающим и запусти `npm run backup`.
- Храни копии отдельно от компьютера/сервера. Не публикуй файлы SQLite: они могут содержать заявки пользователей.

## 6. Публикация в интернете

Перед запуском в production:

1. Выбери хостинг, который поддерживает Node.js 20+ и постоянное хранение файлов (или перенеси БД на PostgreSQL).
2. Настрой HTTPS.
3. Поставь `NODE_ENV=production`, укажи публичный `SITE_URL`, а в Discord OAuth2 добавь Redirect URI вида `https://твой-домен/auth/discord/callback`.
4. В `.env` укажи соответствующий `DISCORD_REDIRECT_URI`, секреты и разрешённые Discord ID.
5. Убедись, что хостинг сохраняет `data/` между перезапусками и выполняет регулярные резервные копии.
6. Не загружай `.env`, `data/` и `backups/` в публичный репозиторий.

Для нескольких экземпляров приложения SQLite-сессии и локальный SQLite-файл потребуют отдельного хранилища/переноса на PostgreSQL и общего session store.

## 7. Что стоит сделать перед реальным открытием заявок

- Добавить политику конфиденциальности и срок хранения заявок.
- Ограничить доступ к резервным копиям и установить график удаления старых копий.
- Проверить сайт на выбранном хостинге и настроить мониторинг/уведомления об ошибках.
- При необходимости подключить Discord-бота для уведомлений о новых заявках и событиях.

## Файлы

- `server.js` — Express API, OAuth2, авторизация, база и аудит.
- `public/index.html` — главная страница.
- `public/styles.css`, `public/app.js` — дизайн и публичная логика.
- `public/admin.html`, `public/admin.css`, `public/admin.js` — админ-панель.
- `public/404.html` — страница ошибки.
- `scripts/backup.js` — резервное копирование базы.

## Поддержка, жалобы и серверные логи

- Страница `/support.html` доступна вошедшим через Discord пользователям. Там можно создать тикет, выбрать категорию (поддержка, жалоба, нарушение или другое) и переписываться с командой.
- В `/admin.html` добавлены вкладки «Жалобы и тикеты» и «Логи сервера». Администратор может читать обращения, отвечать, менять статус и приоритет. Логи сервера показывают последние 300 HTTP-запросов с уровнем, кодом ответа, временем выполнения и IP.
- Переписка и логи сохраняются в SQLite (`data/yushiko.sqlite`). Не публикуйте файл базы данных: в нём могут быть личные сообщения и IP-адреса.
- Для работы всех функций необходимы `npm install`, заполненный `.env` и настроенный Discord OAuth2. Тикеты требуют авторизации Discord.


## Новое: доска «Найди компанию»

На главной странице участники могут публиковать запросы для совместной игры, просмотра аниме, голосового общения и поиска друзей. Для создания запроса требуется вход через Discord. Запросы автоматически истекают через 12 часов; для защиты от спама действует лимит 3 запроса за 30 минут. Авторизованные участники могут откликнуться на запрос один раз. Доска использует SQLite и существующую CSRF-защиту.

Новые таблицы `company_posts` и `company_responses` создаются автоматически при старте сервера; ручная миграция не нужна.
